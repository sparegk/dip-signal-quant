# EXP-003 historical data audit

Scope is fixed in [EXP003_PROTOCOL.md](EXP003_PROTOCOL.md), pushed as `8c55fbc`
before diagnostic acquisition. This audit does not calculate strategy outcomes.

The EXP-002 acquisition JSON preserves 21 malformed-OHLC rejection messages, not
the rejected raw responses. A fresh request cannot identify the exact original
offending rows. The runner labels all new responses `new_diagnostic` and saves
the complete DataFrame, index, provider metadata and raw float values before
calling the unchanged ingestion validator. Generated bytes remain under ignored
`data/exp003/diagnostic/`; frozen `data/market/` files are never written.

```powershell
.\.venv\Scripts\python.exe -W error -m scripts.audit_exp003 --download
# Offline regeneration checks every input hash and idempotently verifies output.
.\.venv\Scripts\python.exe -W error -m scripts.audit_exp003
```

Acquisition records are immutable. A recorded network failure is not automatically
retried; a separately identified diagnostic root is needed for a disclosed new
attempt. `summary.json` contains per-ticker measurements and provenance;
`violations.csv` contains every failed relation and its session/OHLC values.
One row can violate several relations: affected-row counts deduplicate positional
identities, not price observations. Relative gap divides by the larger absolute
operand; spacing units divide by its floating-point spacing. Neither measure is
an acceptance tolerance. Bad schema/numbers remain explicit.

Atomic immutable publication requires a local filesystem supporting hard links.
Readers ignore temporary `.pending-*` files; no partial record is promoted.
SHA-256 checks detect corruption relative to the recorded manifest, not deliberate
rewriting of both data and hashes. Keep independent backups for stronger protection.

Findings will be appended after running the registered audit.
